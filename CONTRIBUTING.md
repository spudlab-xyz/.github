# Contributing to Spudlab

Thank you for contributing. Start with a small, focused change:

1. Search the target repository's issues and pull requests.
2. Open an issue for substantial work so scope can be agreed before implementation.
3. Fork the repository or create a branch, make the change, and add proportionate tests or documentation.
4. Open a pull request using the repository template. Link its issue and describe verification.
5. Respond to review and keep the branch focused.

Repository-specific instructions take precedence. By participating, you agree to the [Code of Conduct](CODE_OF_CONDUCT.md).

## Agent participation and human review

Software agents may triage, implement, review, and respond using the shared `joe-mccarthy` GitHub identity. A response from that account is not proof of independent or human review. Agents must disclose material automated participation and must not approve their own work.

For a human decision, open a public issue in the relevant repository with **Human review requested** in the title. The route is verified as GitHub-native, but a human response-time commitment has not yet been verified. Never post secrets or sensitive reports in an issue.

## Accessibility

For user-facing interfaces and documentation:

- use headings in a logical order and link text that describes its destination;
- provide text alternatives for meaningful images and mark decorative images as decorative;
- preserve keyboard operation, a visible focus indicator, and a sensible focus order;
- associate form controls with clear labels and make error messages specific;
- do not use colour, shape, position, sound, or motion as the only way to convey meaning;
- keep text readable when zoomed and avoid content that flashes; and
- include captions or transcripts for recorded media when it carries information.

In the pull request, describe the affected user journey and the keyboard, screen-reader,
zoom, contrast, or automated checks that are relevant and were run. If a check was not
available, record it as not run and explain the limitation; do not claim conformance
without evidence. Repository-specific accessibility requirements take precedence.
