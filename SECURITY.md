# Security policy

## Supported versions

Each project documents its supported versions, if any. If a project does not publish a supported-versions policy, do not assume that any version will receive security fixes.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability and do not include exploit details, credentials, or personal data in public channels.

GitHub private vulnerability reporting is currently **not enabled** for `spudlab-xyz/.github`, and Spudlab has not verified another private, human-controlled security contact. We therefore cannot currently offer a safe private intake route. This is an explicit launch limitation, not an invitation to report privately to an unlisted account.

If you are affected by an actively exploited vulnerability, follow the relevant platform or hosting provider's security process. A verified private route will be added here only after it is enabled and tested.
