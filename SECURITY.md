# Security policy (draft — not active)

> **Publication blocker:** Spudlab has not yet approved a monitored private fallback contact. Do not publish or rely on this shared policy until that contact is added and tested. Never disclose a suspected vulnerability in a public issue, pull request or discussion.

## Reporting a vulnerability

For a repository with GitHub private vulnerability reporting enabled:

1. Open that repository's **Security** tab.
2. Select **Advisories**, then **Report a vulnerability**.
3. Describe the affected version, impact and minimal reproduction. Remove personal data, credentials and provider-restricted data.

Private vulnerability reporting is a per-repository setting and is not enabled merely because this file is inherited. Maintainers must enable it and verify notifications in each repository.

If the **Report a vulnerability** button is unavailable, **PRIVATE CONTACT REQUIRED BEFORE PUBLICATION:** replace this sentence with an approved, monitored private reporting address. Do not use a public issue as a fallback.

## What to include

Where possible, include:

- the affected repository, version or commit;
- the type and potential impact of the vulnerability;
- safe reproduction steps or a proof of concept;
- relevant configuration, software, firmware or hardware versions; and
- suggested mitigations, if known.

Do not access data that is not yours, degrade services or systems, or expose the issue more widely than needed to report it. Maintainers will coordinate disclosure according to the risk and available volunteer capacity. No response or resolution time is promised.

Ordinary setup, usage and bug questions belong in the repository's normal support channels; see the [support guidance](https://github.com/spudlab-xyz/.github/blob/main/SUPPORT.md).
